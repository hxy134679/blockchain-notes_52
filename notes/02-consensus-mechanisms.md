# 共识机制

共识机制（Consensus Mechanism）解决的是分布式系统的核心问题：**在部分节点可能出错或作恶的情况下，如何让所有节点对账本状态达成一致**。

## 1. 为什么需要共识

在中心化系统中，数据库由单一权威维护；而在去中心化网络中，节点分布各地、互不信任，且存在网络延迟、节点宕机甚至恶意节点（拜占庭行为）。共识机制就是在这样的环境中确定"由谁记账、如何验证、出现分歧怎么办"的规则集合。

## 2. 主流共识机制对比

| 机制 | 代表项目 | 核心思想 | 优点 | 缺点 |
| ---- | -------- | -------- | ---- | ---- |
| PoW（工作量证明） | 比特币 | 竞争算力解哈希难题获得记账权 | 安全性经过长期验证 | 能耗高、吞吐量低 |
| PoS（权益证明） | 以太坊 2.0 | 按质押权益比例随机选择出块者 | 能耗低、扩展性好 | "富者愈富"争议、需防长程攻击 |
| DPoS（委托权益证明） | EOS | 持币人投票选出少数代表节点记账 | 效率高 | 中心化程度较高 |
| PBFT（实用拜占庭容错） | Hyperledger Fabric（部分环节） | 节点两两广播投票，达到 2/3 多数即确认 | 确定性最终一致、无分叉 | 通信复杂度高，适合节点数有限的联盟链 |
| Raft | 部分联盟链/orderer | 领导者选举 + 日志复制 | 实现简单、性能好 | 只容错宕机，不容错作恶 |

## 3. PoW：以算力换取信任

比特币的工作量证明要求矿工不断调整 Nonce，使区块头的哈希值小于目标难度值。由于哈希运算无法预测，只能暴力尝试，找到有效解平均需要海量计算——这使篡改历史区块需要重做其后所有区块的工作量证明，成本极高，从而保证账本安全。

## 4. PoS：以权益绑定利益

以太坊转向 PoS 后，验证者需质押 32 ETH 参与 出块与验证，作恶将被罚没质押金（Slash）。其逻辑是：让作恶者付出真金白银的代价，用经济激励替代算力竞争。

## 5. 联盟链场景下的共识选择

联盟链节点数量有限且身份已知，通常选择 PBFT 或 Raft 类算法：牺牲部分去中心化，换取**秒级确认、无分叉、高吞吐**，更符合企业级应用对确定性的要求。

## 6. 小结

不存在"最好"的共识机制，只有场景适配：公链追求开放环境下的安全与去中心化，联盟链追求可控环境下的性能与最终一致性。
