# 联盟链与 Hyperledger Fabric

## 1. 公链与联盟链

区块链按准入方式可分为：

| 类型 | 准入方式 | 代表 | 适用场景 |
| ---- | -------- | ---- | -------- |
| 公有链 | 无需许可，任何人可参与 | 比特币、以太坊 | 加密货币、DeFi 等公开场景 |
| 联盟链 | 需许可，由联盟成员共同维护 | Hyperledger Fabric、FISCO BCOS | 供应链金融、政务、溯源等企业级场景 |
| 私有链 | 单一组织控制 | — | 企业内部审计与存证 |

联盟链保留了区块链的**多方共识、不可篡改、可追溯**等核心价值，同时通过准入机制获得更好的性能与合规性，是我国产业区块链落地的主要形态。

## 2. Fabric 核心架构

Hyperledger Fabric 是 Linux 基金会主导的企业级联盟链框架，其核心设计：

- **多通道（Channel）机制**：不同业务方可建立独立的数据隔离通道，满足隐私要求；
- **执行-排序-验证架构**：交易先在背书节点模拟执行，再由排序节点排序出块，最后由记账节点验证提交，与公链"先排序后执行"截然不同，大幅提升吞吐量；
- **智能合约（链码 Chaincode）**：可用 Go、Java、Node.js 等通用语言编写，降低开发门槛；
- **可插拔共识**：支持 Raft 等排序服务，按需替换。

## 3. 一笔交易的生命周期

1. 客户端向背书节点提交交易提案；
2. 背书节点模拟执行链码并签名背书；
3. 客户端收集满足背书策略的签名，提交给排序节点；
4. 排序节点将交易排序打包成块；
5. 记账节点验证背书策略与读写集，提交状态数据库。

## 4. 学习建议

- 先用 `fabric-samples` 测试网络跑通 `test-network` 示例；
- 阅读官方文档 "Key Concepts" 部分，理解背书策略与 MSP（成员服务提供者）；
- 尝试用 Go 编写一个简单的资产转移链码。
